# migrations/

Generated by `bun run db:generate` from `src/schema/`, applied with
`bun run db:migrate` against `DATABASE_URL` (the **direct**, unpooled Neon
URL — see docs/infrastructure.md). Commit every file this folder holds,
`meta/` included: `meta/_journal.json` is the list `db:migrate` applies, and
the newest `meta/*_snapshot.json` is what `db:generate` diffs the schema
against.

`0000_initial.sql` is the whole schema at the first release. Each later change
is a new numbered migration; a released one is never edited.

Never hand-edit a generated file except to append extension or grant
statements, as `0000_initial.sql` does, or to prepend the data fixes a new
constraint needs, under a `-- Hand-edited:` line. Before generating a
constraint migration, write a query that lists the rows it would refuse and
run it against a copy of production.

`0000_initial.sql` ends with a conditional
`REVOKE UPDATE, DELETE ON org_activity FROM nothingleft_app`. It does nothing
if the role does not exist when the migration runs, and it is not re-run when
the role is created later. The audit log's immutability is therefore enforced
by the provisioning in
[infrastructure.md](../../../docs/infrastructure.md#database-roles), not by
this statement alone: create the role before the first migration, or run the
grant script there after it, and always run the verification queries.
