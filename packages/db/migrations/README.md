# migrations/

Generated by `bun run db:generate` from `src/schema/`, applied with
`bun run db:migrate` against `DATABASE_URL` (the **direct**, unpooled Neon
URL — see docs/infrastructure.md). Never hand-edit a generated file except to
append extension or grant statements, as `0000_init_identity.sql` does, or to
prepend the data fixes a new constraint needs, under a `-- Hand-edited:` line,
as `0005` and `0017` do. Before generating a constraint migration, list the
rows it would refuse (`scripts/precheck-0017.sql` is the pattern).

Migration `0001` appends a conditional
`REVOKE UPDATE, DELETE ON org_activity FROM nothingleft_app`. It does nothing
if the role does not exist when the migration runs, and it is not re-run when
the role is created later. The audit log's immutability is therefore enforced
by the provisioning in
[infrastructure.md](../../../docs/infrastructure.md#database-roles), not by
this statement alone: create the role before the first migration, or run the
grant script there after it, and always run the verification queries.

Migration `0019` is reordered by hand: `project_id` is added nullable, backfilled from the
parent row, then made `NOT NULL`, and each referenced UNIQUE key is created before its foreign key.

`0020` was generated in two passes and joined into one file, with the hand-edited backfill
between them: drizzle-kit asks interactively whether an added column renames a dropped one,
and that prompt cannot run without a terminal. The second pass only dropped columns.

`0021` is data only, written by hand from `drizzle-kit generate --custom`: it clears stored
generated-avatar URLs, which are now built at read time.
